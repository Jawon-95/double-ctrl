# 项目背景

Double Ctrl 想解决的问题：有道词典的“双击 Ctrl 划词翻译”很好用，但安装包很大，而且在一些地方不起作用，
比如资源管理器的重命名框和地址栏。这里只需要这一个功能，所以单独做一个小工具。

本文记录使用过程中观察到的现象和由此做出的设计选择。

## 观察到的现象

- 划词时，剪贴板会短暂变化：先由目标程序写入，随后由词典程序写回。说明取词方式是模拟复制，读完再恢复。
- 词典软件设置了不取词的程序列表，Excel、Visual Studio、Eclipse、Xshell 等都在其中，这能解释“某些软件里无效”。
- 资源管理器不在这个列表里，所以重命名框失效另有原因。可能和按键时机或弹窗抢走焦点有关，**这一点未能证实**。

## 设计选择

| 问题 | Double Ctrl 的做法 |
| --- | --- |
| 模拟复制不总是可靠 | 先直接读取控件和 UI Automation，只有都不行才模拟复制 |
| 弹窗抢焦点会打断重命名 | 有选中文字时弹窗不激活 |
| 复制动作污染剪贴板 | 保存全部格式并恢复，同时清掉 Win+V 里新增的那一条 |
| 终端里 Ctrl+C 是中断信号 | 终端类程序改用 Ctrl+Insert |
| 键盘钩子超时后被系统摘除 | 用 Raw Input 监听，不在系统按键路径上 |
| 安装包太大 | 用系统自带的 .NET Framework，单文件 exe，不内置浏览器内核 |

各处实现的细节和失效时的修法见 [MAINTENANCE.md](MAINTENANCE.md)。
